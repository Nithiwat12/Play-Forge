# สเปคเกมใหม่: "ทายคำบนหัว" (WordHead) — สำหรับเพิ่มเข้า GameCen

แรงบันดาลใจจากคลิป "อะไรอยู่บนหัวกูวะ" (ช่อง RUBSARB) ซึ่งเป็นเกมแนวเดียวกับ Hedbanz สากล:
ผู้เล่นแต่ละคนมีคำศัพท์ติดอยู่ "บนหัว" ที่ตัวเองมองไม่เห็น แต่คนอื่นในห้องเห็นหมด แล้วต้องถามคำถาม
แบบใช่/ไม่ใช่ กับเพื่อนร่วมห้องเพื่อไล่เดาว่าคำบนหัวตัวเองคืออะไร

เอกสารนี้เขียนเป็น "พรอมต์สเปค" สำหรับส่งให้ Claude (หรือคนอื่น) ใช้ implement เกมนี้เข้าไปใน
โปรเจกต์ GameCen ที่มีอยู่แล้ว (server: Node/Express/Socket.IO + Prisma, client: React/Vite) โดยให้
ทำตามสถาปัตยกรรมเดียวกับเกม Spy Hunt (Spyfall) ที่มีอยู่แล้วในโปรเจกต์ทุกประการ — เกมใหม่ต้องเป็น
game-agnostic-compatible เหมือนเกมแรก คือ logic เฉพาะเกมอยู่ใน `server/src/games/wordhead/*` และ
`client/src/games/wordhead/*` เท่านั้น ไม่แตะ layer กลาง (Room/Socket/Scoreboard/Continue-vote system)
เกินความจำเป็น

---

## 1. ชื่อเกมที่แนะนำ

**"ทายคำบนหัว"** (slug: `wordhead`) — ตั้งชื่อใหม่ไม่ใช้ชื่อ "Hedbanz" ตรงๆ (เป็นชื่อสินค้าจดทะเบียนของ
ค่ายอื่น) กลไกการเล่นเป็นกลไกเกมปาร์ตี้ทั่วไปที่มีมานานหลายเวอร์ชัน ไม่ติดปัญหาลิขสิทธิ์ แต่ชื่อ/แบรนด์ควร
เป็นของตัวเอง

## 2. จำนวนผู้เล่น

3–8 คน (เหมือน Spy Hunt) — ต่ำกว่า 3 คนวงคำถามจะจืดเกินไป, เกิน 8 คนแต่ละคนต้องรอคิวนานเกินไป

## 3. ต้องรองรับการเล่น 2 รูปแบบพร้อมกันในระบบเดียว (ไม่ใช่โหมดให้เลือก)

ผู้เล่นในห้องเดียวกันอาจเป็น:

- **นั่งเล่นด้วยกันในที่เดียว** ต่างคนต่างเปิดเว็บ/มือถือของตัวเอง คุยกันด้วยปากเปล่าได้เลย
- **เล่นออนไลน์แยกที่กัน** ไม่เห็นหน้ากัน ต้องสื่อสารผ่านแอปอย่างเดียว

สองแบบนี้**ต้องเล่นในห้องเดียวกันแบบผสมกันได้ด้วยซ้ำ** (เช่น 3 คนนั่งด้วยกันในบ้าน อีก 2 คนต่อออนไลน์
จากที่อื่น) เพราะฉะนั้น**ห้ามออกแบบเป็น toggle/setting** "โหมดเล่นด้วยกัน" vs "โหมดออนไลน์" ที่ต้องเลือก
อย่างใดอย่างหนึ่งตอนสร้างห้อง — ต้องออกแบบกลไกเกมให้ใช้งานได้ดีทั้งสองแบบพร้อมกันโดยระบบไม่ต้องรู้
เลยว่าใครนั่งอยู่ตรงไหน

ผลต่อการออกแบบที่ต้องระวัง:

- ขั้นตอน "ถามคำถาม" ห้ามบังคับให้พิมพ์ข้อความคำถามเสมอไป เพราะคนที่นั่งด้วยกันจะถามด้วยปากเปล่า
  อยู่แล้ว ไม่อยากพิมพ์ซ้ำ — ให้ `text` ใน action `ASK_QUESTION` เป็น **optional**: ถ้าพิมพ์มาก็โชว์ log
  ให้คนอื่นอ่าน (มีประโยชน์กับฝั่งที่เล่นออนไลน์ซึ่งไม่ได้ยินเสียง), ถ้าไม่พิมพ์ (กดปุ่ม "ถามคำถาม (พูดสด)"
  เฉยๆ) ระบบก็แค่เปิด "หน้าต่างรอคำตอบ" ให้ผู้เล่นคนอื่นกด ใช่/ไม่ใช่/ไม่แน่ใจ ได้เลยโดยไม่มีข้อความคำถาม
  ใน log (หรือใส่ log เป็น "(ถามด้วยเสียง)" แทน)
- การ**ตอบคำถาม** ต้องทำผ่านแอปเสมอไม่ว่าจะนั่งด้วยกันหรือไม่ (กดปุ่มในมือถือตัวเอง) เพราะเป็นกลไกหลัก
  ที่ตัดสินผลเกม จะได้เก็บสถิติ/คะแนนถูกต้องเหมือนกันทั้งสองสถานการณ์ — ส่วนนี้ไม่ต้องปรับอะไรเพราะเป็น
  การกดปุ่ม ไม่ใช่การพิมพ์ อยู่แล้ว
- ห้ามมี feature ไหนที่ "รู้" หรือ "สันนิษฐาน" ว่าผู้เล่นอยู่ด้วยกันหรือไม่ (เช่น ห้ามปิดช่องพิมพ์คำถามถ้า
  ตรวจพบว่า "น่าจะนั่งด้วยกัน" เพราะระบบไม่มีทางรู้จริง และห้องอาจผสมทั้งสองแบบตามที่บอกไปข้างบน)
  ทุกอย่างต้อง fallback ให้เล่นจบเกมได้แบบไม่ต้องพิมพ์อะไรเลย ถ้าอยากพิมพ์เพิ่มก็ทำได้เฉยๆ

สรุป: นี่ไม่ใช่ "ฟีเจอร์ใหม่" ที่ต้องสร้างเพิ่มต่างหาก แต่เป็น**ข้อบังคับในการออกแบบ UI/action ของทุก
ขั้นตอน** ว่าห้ามมีขั้นตอนไหนบังคับพิมพ์ข้อความจนคนที่นั่งเล่นด้วยกันรำคาญ และห้ามมีขั้นตอนไหนที่พึ่งพา
การอยู่ที่เดียวกันจนคนเล่นออนไลน์เล่นไม่ได้

## 4. กลไกหลัก (มุมมองผู้เล่น)

1. ต้นรอบ ระบบสุ่มคำศัพท์ให้ผู้เล่น **ทุกคน** คนละ 1 คำ (จากคลังคำ - ดูหมวดหมู่ข้อ 6) แต่ละคนจะ
   **มองไม่เห็นคำของตัวเอง** แต่เห็นคำของคนอื่นในห้องหมด (แสดงเป็นบับเบิลลอยเหนือชื่อผู้เล่นแต่ละคน
   ในหน้าเกม)
2. เรียงคิวผู้เล่น (ตามลำดับเข้าห้อง หรือสุ่มตอนเริ่มรอบก็ได้ - ให้สุ่มเพื่อความสนุก)
3. ผู้เล่นที่ถึงคิวมี 2 ทางเลือกในตาตัวเอง:
   - **ถามคำถามใช่/ไม่ใช่** เกี่ยวกับคำของตัวเอง (พิมพ์คำถามอิสระ หรือไม่พิมพ์ก็ได้ - ดูข้อ 3 เรื่อง
     รองรับเล่นนั่งด้วยกัน) คำถาม (ถ้าพิมพ์มา) จะโชว์ให้ทุกคนเห็น แล้วให้ **ผู้เล่นคนอื่นในห้อง** กดตอบ
     แบบ crowd-vote (แต่ละคนกด "ใช่" / "ไม่ใช่" / "ไม่แน่ใจ" อิสระ) ระบบสรุปคำตอบเสียงส่วนใหญ่ให้
     อัตโนมัติ แล้วขึ้น log ว่า "รอบที่ N: <คำถาม หรือ (ถามด้วยเสียง)> → ส่วนใหญ่ตอบ <ใช่/ไม่ใช่/ไม่แน่ใจ>"
   - **ทาย** คำของตัวเอง (พิมพ์หรือเลือกจาก dropdown คำใบ้บางส่วน) — ทายถูกจบตาแบบได้แต้ม
     ทายผิดเสียตา (ไม่เสียสิทธิ์เดา แค่เสียคิว ต้องรอเวียนมาใหม่)
   - มี**เวลาต่อคิว** (ตั้งค่าได้ตอนสร้างห้อง เช่น 20–45 วินาที) ถ้าหมดเวลาไม่ทำอะไรเลย ตาเปลี่ยน
     ไปคนถัดไปอัตโนมัติ (ไม่ทายไม่ถือว่าผิด)
4. ผู้เล่นที่ทายถูกแล้ว **ออกจากคิวถามคำถาม** แต่ยังอยู่ในห้องเพื่อช่วยตอบคำถามคนอื่นต่อได้ (คล้าย
   ผู้เล่นที่ตายแล้วในเกมอื่นๆ ที่ยังดูเกมต่อได้)
5. จบรอบเมื่อ **ทุกคนทายถูกหมด** หรือ **หมดเวลารวมของรอบ** (เช่น 5 นาที ตั้งค่าได้) — ใครยังไม่ทาย
   ถูกตอนหมดเวลาจะไม่ได้แต้มจากคำนั้น
6. หลังจบรอบ ใช้ **ระบบ continue-vote ที่มีอยู่แล้วในแพลตฟอร์ม** (เหมือน Spy Hunt) ถามว่าจะเล่นต่อ
   รอบใหม่ไหม (คำใหม่ทั้งหมด) — ไม่ต้องสร้างระบบนี้ใหม่

## 5. คะแนน

- ทายถูก: ให้แต้มแปรผกผันกับจำนวนคำถามที่ใช้ไปก่อนทายถูก เช่น
  - ทายถูกภายใน 1–3 คำถาม → 3 แต้ม
  - 4–6 คำถาม → 2 แต้ม
  - มากกว่านั้น (หรือทายมั่วโดยยังไม่ถามเลย) → 1 แต้ม
- ทายผิด: ไม่หักแต้ม แค่เสียตา (กันไม่ให้กลัวการทายจนไม่กล้าเล่น)
- ไม่ทายถูกเลยตอนจบรอบ: 0 แต้มสำหรับรอบนั้น
- แต้มสะสมข้ามหลายรอบ ใช้ **ระบบ Scoreboard ที่มีอยู่แล้ว** (`ScoreboardService`, `ScoreboardTable`
  component) เหมือน Spy Hunt ทุกประการ — แค่ต้อง map ให้ `RoundScoreEntry.scores` เก็บแต้มของเกมนี้
  แทน ไม่ต้องสร้าง UI ตารางคะแนนใหม่

## 6. คลังคำศัพท์ + หมวดหมู่

ออกแบบให้มีหมวดหมู่คล้ายระบบ category ที่เพิ่งสร้างให้ Spy Hunt (`SPYFALL_CATEGORIES` /
`categoryMode: RANDOM | FIXED | PER_ROUND`) — เอาแนวคิดเดียวกันมาใช้กับคำศัพท์เกมนี้ได้เลย
(คนละคลังข้อมูล คนละไฟล์ แต่ pattern การเลือกโหมดเหมือนกัน จะได้ UI ฝั่ง CreateRoom หน้าตาคุ้นเคย)

ตัวอย่างหมวดหมู่ที่แนะนำ (คิดเอง เปลี่ยนได้ตามต้องการ) — **หลีกเลี่ยงชื่อคนจริง/ตัวละครที่มีลิขสิทธิ์
ชัดเจน ใช้เป็นหมวดกว้างๆ แทน** เพื่อความปลอดภัยด้าน IP:

| หมวด | ตัวอย่างคำ (10–20 คำต่อหมวดตอน implement จริง) |
|---|---|
| สัตว์ | ช้าง, แมว, นกฮูก, จระเข้, ผึ้ง, ปลาหมึก, อูฐ, เต่า |
| สิ่งของในบ้าน | ร่ม, หมอน, กระทะ, พัดลม, กุญแจ, แปรงสีฟัน, เตารีด |
| อาหาร/ขนมไทย | ส้มตำ, ทุเรียน, ข้าวเหนียวมะม่วง, ต้มยำกุ้ง, ขนมครก |
| อาชีพ | หมอ, นักดับเพลิง, ครู, นักบิน, ชาวประมง, ตำรวจ |
| สถานที่ | ภูเขา, ตลาดนัด, สนามบิน, วัด, โรงพยาบาล |
| ตัวละครสมมติทั่วไป (ไม่ระบุเรื่อง) | ซูเปอร์ฮีโร่, เจ้าหญิงในนิทาน, ผีตัวตลก, หุ่นยนต์, มนุษย์ต่างดาว |

โครงสร้างข้อมูลแนะนำ (mirror รูปแบบ `server/src/games/spyfall/locations.ts`):

```ts
export const WORDHEAD_CATEGORIES = [
  { id: "animals", label: "สัตว์" },
  { id: "household", label: "สิ่งของในบ้าน" },
  { id: "food", label: "อาหาร/ขนมไทย" },
  { id: "jobs", label: "อาชีพ" },
  { id: "places", label: "สถานที่" },
  { id: "fictional", label: "ตัวละครสมมติทั่วไป" },
] as const;

export interface WordHeadWord {
  text: string;
  category: (typeof WORDHEAD_CATEGORIES)[number]["id"];
  // คำใบ้สั้นๆ ไว้โชว์ตอน dropdown ช่วยทาย (ถ้าอยากทำ) - optional
}
export const WORDHEAD_WORDS: WordHeadWord[] = [ /* ... */ ];
```

ตั้งค่าห้องให้เลือกได้เหมือน Spy Hunt: สุ่มทุกรอบ / ล็อกหมวดเดียวทั้งแมตช์ / ให้หัวหน้าห้องเลือกก่อน
แต่ละรอบ (เอาโค้ด `categoryMode` pattern จาก `RoomSettings`/`CreateRoom.tsx`/`gameSocket.ts`'s
`pendingCategoryPicks` มาปรับใช้ได้เกือบตรงตัว)

## 7. State machine ฝั่ง engine (มิเรอร์ `SpyfallGame.ts`)

Phase enum ที่แนะนำ: `"IN_PROGRESS" | "FINISHED"` (ไม่มี VOTING/REVEALED เหมือน Spyfall เพราะเกมนี้
ไม่มีการโหวตจับสปาย)

Public state ต่อผู้เล่น (ส่งเหมือนกันให้ทุกคน) ต้องมี:

- `players`: userId, username, `hasGuessedCorrectly: boolean`, `questionsAskedThisTurn` ฯลฯ
- `currentTurnUserId`: ใครกำลังจะถาม/ทาย
- `turnEndsAt` / `roundEndsAt`: ใช้กับ Timer component ที่มีอยู่แล้ว
- `log`: ประวัติคำถาม-คำตอบ (เหมือน `SpyfallLogEntry`) - แต่ละ entry ต้องรองรับ "ไม่มีข้อความคำถาม"
  (ดูข้อ 3) เช่น field `text: string | null`
- `wordsByUserId`: **สำคัญมาก** ต้องเป็นส่วนหนึ่งของ **private state ต่อ socket** ไม่ใช่ public state
  ตรงๆ — ต้อง apply กฎเดียวกับที่ `SpyfallGame.getPrivateState(userId)` ทำ: คำนวณแยกให้แต่ละ userId
  โดย **ตัดคำของ userId นั้นเองออกจาก map ที่ส่งกลับ** ก่อนส่ง เพื่อไม่ให้ client เห็นคำตัวเอง
  (ห้ามส่ง public state ที่มี map คำของทุกคนแบบดิบๆ ไปให้ client แล้วหวังว่า frontend จะซ่อนเอง —
  ต้องกรองที่ server เหมือนที่ระบบเดิมกันไม่ให้ client เห็น `spyUserId` ก่อนเวลาอันควร)
- `myNotes: string`: สมุดจดส่วนตัว (ดูข้อ 9) - อยู่ใน private state เท่านั้น ห้ามหลุดไปที่ public state
  หรือ private state ของคนอื่นเด็ดขาด

Action types (namespaced เหมือน `SPYFALL_ACTIONS`):

```ts
export const WORDHEAD_ACTIONS = {
  ASK_QUESTION: "wordhead:askQuestion",      // { text?: string } - text เป็น optional (ดูข้อ 3), เฉพาะคนที่ถึงตา
  ANSWER_QUESTION: "wordhead:answerQuestion", // { answer: "YES" | "NO" | "UNSURE" } - ทุกคนยกเว้นเจ้าของตา
  GUESS: "wordhead:guess",                    // { guess: string } - เฉพาะคนที่ถึงตา
  PASS_TURN: "wordhead:passTurn",             // ไม่บังคับมี - ให้สละตาก่อนหมดเวลาได้
  UPDATE_NOTES: "wordhead:updateNotes",       // { notes: string } - แก้สมุดจดตัวเอง (ดูข้อ 9)
} as const;
```

Flow ต่อ 1 คำถาม: `ASK_QUESTION` → เปิด "answer window" (เช่น 10 วิ) → เก็บโหวตจาก
`ANSWER_QUESTION` ของผู้เล่นคนอื่นทุกคน (คล้ายกลไก `votePoll` ใน Spyfall ที่นับเสียงแบบ secret-ish
ballot แล้วสรุปเป็น public tally) → เมื่อครบเวลาหรือทุกคนตอบแล้ว สรุปเสียงส่วนใหญ่ ต่อ log แล้วเปลี่ยน
ตาไปคำถาม/การทายถัดไปของคนเดิม (จนกว่าจะทายถูก/ตาไปคนถัดไปเมื่อ "askQuestion" ครบโควตาต่อตา
ถ้าอยากจำกัด เช่น 1 คำถามต่อ 1 ตาแล้วส่งไม้ต่อคนถัดไปเลย เพื่อความเร็ว - **แนะนำแบบนี้** ง่ายกว่า

## 8. ระบบที่ "ห้ามสร้างใหม่" — ใช้ของเดิมในแพลตฟอร์มให้หมด

โปรเจกต์นี้มี generic layer ที่ตั้งใจให้ใช้ร่วมกันข้ามเกมอยู่แล้ว ห้าม implement ซ้ำ:

- Room lifecycle (WAITING/PLAYING/FINISHED), lobby, join/leave/disband → `RoomService` เดิม
- Continue-vote ("เล่นต่อไหม") หลังจบรอบ, auto-disband ห้องเมื่อจบแมตช์ → `gameSocket.ts` เดิม
  (แค่ให้ engine คืนค่า `GameResult.details` ที่มี field ที่ generic layer อ่านได้แบบ opaque
  เหมือนที่ Spyfall ใส่ `locationCategory` ไว้ให้ระบบ category-pending อ่าน)
- Scoreboard สะสมข้ามรอบ, ตารางคะแนนรวม → `ScoreboardService` + `ScoreboardTable` component เดิม
- ประวัติเกม/หน้า History → ใช้ `UserService.getHistoryForUser` เดิมได้เลย (game-agnostic อยู่แล้ว,
  `resultData` เป็น opaque JSON ต่อเกม)
- Presence/reconnect, host reassignment → เดิมหมด (สำคัญกับเกมนี้เป็นพิเศษ เพราะมีทั้งคนนั่งด้วยกัน
  และคนออนไลน์ผสมกันในห้องเดียว โอกาสหลุดการเชื่อมต่อของฝั่งออนไลน์มีมากกว่า ต้อง reconnect กลับมา
  แล้วเห็น state ล่าสุดถูกต้อง รวมถึง `myNotes`/`wordsByUserId` ของตัวเองด้วย)

สิ่งที่ต้องสร้างใหม่จริงๆ มีแค่:

1. `server/src/games/wordhead/` — WordHeadGame.ts (extends BaseGame), WordHeadState.ts (types),
   words.ts (คลังคำ+หมวด), WordHeadRules.ts (validation ของ payload แต่ละ action), index.ts
   (register เข้า GameRegistry แบบเดียวกับ `spyfall/index.ts`)
2. `client/src/games/wordhead/` — WordHeadGame.tsx (คอมโพเนนต์หลัก, ลงทะเบียนใน
   `client/src/games/registry.tsx`), WordBubble.tsx (โชว์คำของคนอื่นเหนือหัว), QuestionLog.tsx,
   AnswerButtons.tsx, GuessInput.tsx, NotesPad.tsx (สมุดจดส่วนตัว - ข้อ 9), words-categories.ts
   (คู่กับฝั่ง server เหมือนที่ Spyfall ทำ `categories.ts` คู่กับ `locations.ts`)
3. เพิ่มแถวเกมใหม่ในตาราง `games` (Prisma seed) — slug `wordhead`, minPlayers 3, maxPlayers 8
4. `CreateRoom.tsx` ต้องรองรับ settings เฉพาะเกมนี้แบบ conditional (โชว์เฉพาะตอนเลือกเกม wordhead)
   — ตอนนี้หน้า CreateRoom เป็น generic ใช้ร่วมทุกเกม แต่มี field เฉพาะ Spyfall (discussionMinutes,
   category) ฝังไว้ตรงๆ อยู่แล้ว ให้ทำ pattern เดียวกัน คือเช็ค `gameSlug === "wordhead"` ก่อนโชว์
   ฟิลด์ที่เกมนี้ใช้ (เช่น เวลาต่อคิวถาม, เวลารวมต่อรอบ, categoryMode ของคำศัพท์)

## 9. สมุดจดส่วนตัวของผู้เล่น (Personal Clue Notes)

เพิ่มเติมตามที่ขอ: ผู้เล่นแต่ละคนอยากมี "สมุดจด" ส่วนตัวในหน้าเกม ไว้พิมพ์บันทึกเก็บเบาะแสที่ได้จาก
คำตอบที่ผ่านมา เช่น จดเองว่า "ไม่ใช่สัตว์, บินได้, เจอในบ้าน" เพื่อช่วยตัดสินใจว่าจะถามคำถามต่อไปว่า
อะไร หรือจะทายเลยดี - พูดง่ายๆ คือเป็น **ตัวช่วยตัดสินใจของคนถามเอง** ไม่ใช่กลไกที่ระบบเอาไปตัดสิน
ผลแพ้ชนะ

รายละเอียดที่ควรมี:

- เป็น text area ส่วนตัว **เห็นเฉพาะเจ้าของ** ไม่ broadcast ให้คนอื่นเห็น (เก็บใน private state
  เหมือน `wordsByUserId`/`locationOptions` ของ Spyfall)
- แก้ไขได้ตลอดเวลา ไม่ใช่แค่ตอนถึงตาตัวเอง (จะได้จดระหว่างรอตาได้ด้วย)
- ไม่บังคับใช้ - มีไว้ให้พิมพ์เฉยๆ ไม่ใช่ input ที่ระบบเอาไปตัดสินผลเกม (คนละอย่างกับ log คำถาม-คำตอบ
  ที่ระบบ auto-generate ให้อยู่แล้วในข้อ 7 - นี่คือสมุดเสริมที่ผู้เล่นพิมพ์เอง ต้องมีทั้งสองอย่างแยกจากกัน)
- เก็บที่ **server-side private state** (ผูกกับ `userId` ในเกมนั้น) ไม่ใช่แค่ local storage ฝั่ง client
  เฉยๆ เพื่อกันหายตอนรีเฟรชหน้า/สลับอุปกรณ์ระหว่างเล่น (สำคัญกับกรณีเล่นออนไลน์ที่หลุดการเชื่อมต่อ
  บ่อยกว่าคนนั่งเล่นด้วยกัน)

## 10. ประเด็นที่ควรถามผู้เล่น/เจ้าของโปรเจกต์ก่อนเริ่มโค้ดจริง

1. ตอบคำถามแบบ **โหวตเสียงส่วนใหญ่จากทุกคนในห้อง** หรือ **ให้คนเดียวที่ระบบสุ่ม/เลือกเป็นคนตอบ**
   ต่อคำถาม? (เอกสารนี้ default เป็นแบบโหวตเสียงส่วนใหญ่ เพราะสนุกกว่าและลดปัญหา "คนตอบตอบมั่ว")
2. จำกัด "1 คำถาม = 1 ตา" (ส่งไม้ต่อทันที) หรือให้ถามได้เรื่อยๆ จนกว่าจะทายถูก/หมดเวลาของตาเอง?
3. อยากได้ dropdown คำใบ้ช่วยทาย (เลือกจากลิสต์คำในหมวดนั้น) หรือให้พิมพ์คำตอบอิสระแล้วระบบเทียบ
   ข้อความคร่าวๆ (fuzzy match กันพิมพ์ผิด)?
4. จำนวนคำถามสูงสุดต่อคน/รอบ มีเพดานไหม หรือปล่อยจนกว่าเวลารวมของรอบจะหมด?
5. สมุดจดส่วนตัว (ข้อ 9) อยากให้ **ทุกคน** มีสมุดจดของตัวเองได้ตลอดเวลา หรือให้มีเฉพาะ **คนที่กำลัง
   ทายคำของตัวเองอยู่ตอนนั้น** เท่านั้น?

**สรุปสั้น:** งานนี้คือการเพิ่มเกมที่สองเข้า GameCen ตามสถาปัตยกรรม game-agnostic ที่มีอยู่แล้ว
(เหมือนตอนที่ Spy Hunt/Spyfall ถูกเพิ่มเข้ามาเป็นเกมแรก) กลไกหลักคือ "ทายคำบนหัวตัวเองผ่านคำถาม
ใช่/ไม่ใช่จากเพื่อนร่วมห้อง" ใช้ระบบ scoreboard/continue-vote/history/room ของแพลตฟอร์มเดิมทั้งหมด
สร้างใหม่แค่ engine เฉพาะเกม + UI เฉพาะเกม + คลังคำศัพท์ โดยทั้งระบบต้องรองรับทั้งคนที่นั่งเล่นด้วยกัน
และคนที่เล่นออนไลน์แยกที่กันในห้องเดียวกันได้เลยโดยไม่มีโหมดแยก แถมมีสมุดจดส่วนตัวให้ผู้เล่นบันทึก
เบาะแสระหว่างเล่นด้วย
