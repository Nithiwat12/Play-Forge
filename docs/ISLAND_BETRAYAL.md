# Island Betrayal — Full Game update

ใช้ข้อกำหนด `Markdown ที่วาง (1)(1).md` ฉบับล่าสุด แทนกติกา Island รุ่น PDF เดิม ไม่เปลี่ยนไฟล์กติกา Spy/WordHead

## สถาปัตยกรรมและจุดเชื่อม

ใช้ React/TypeScript/Tailwind, Zustand, CreateRoom/JoinRoom/Lobby/PlayPage/History, บัญชี/JWT, Socket.IO, BaseGame/GameRegistry/GameManager, Timer/Card/Button และ chat เดิมของ Island ไม่สร้างระบบบัญชี ห้อง หรือล็อบบี้ใหม่

Prisma/PostgreSQL ใช้ Room.settings และ GameSession/GameHistory JSON เดิม ไม่มีตารางซ้ำ เพิ่มเฉพาะ migration ปรับ catalog Island ให้รองรับ 15 คน

เพิ่ม role definitions ใน GameRegistry และ component กลาง RoleConfiguration สำหรับสร้างห้อง/ล็อบบี้ เกมใหม่สามารถประกาศ definitions เพื่อใช้ซ้ำได้ เกมเก่าที่ไม่ประกาศ definitions ไม่เปิดให้ตั้งบทบาทหรือเปลี่ยนกติกา

## เปิดใช้งาน

จากโฟลเดอร์ GameCen หลังตั้ง `.env` ตาม README เดิม:

```sh
npm run install:all
npm run prisma:generate
npm run prisma:deploy --prefix server
npm run build:server
npm run build:client
```

ฐานข้อมูลใหม่ใช้ `npm run seed` เดิมได้ ฐานข้อมูลที่มี Island รุ่นแรกแล้วต้องรัน migration `20260912230000_island_roles_and_world` เพื่อเพิ่มจำนวนผู้เล่นสูงสุดเป็น 15

## ตั้งค่าบทบาท

4–6 คนมี Spy 1 / 7–10 คนมี Spy 2 / 11–15 คนมี Spy 3 เป็นค่าเริ่มต้น หัวหน้าเลือกจำนวนแน่นอน ผู้เล่นต่อ Spy เปอร์เซ็นต์ หรือค่าแนะนำ พร้อมปรับเพดานได้ Survivor เติมจำนวนที่เหลือ ต้องมีอย่างน้อย 1 คน

แก้บทบาทในล็อบบี้ได้ก่อนเริ่มเกม ทุกคนต้องกดพร้อมใหม่หลังบันทึก ใช้ per-room setup lock ป้องกันคำขอแก้บทบาทกับเริ่มเกมชนกัน เมื่อเริ่มแล้วสุ่มบทบาทบน server และล็อกตลอดเกม reconnect ไม่สุ่มใหม่

ปกติแต่ละคนรู้เฉพาะบทบาทตัวเอง เจ้าห้องเลือกให้ Spy รู้จักเพื่อน Spy เป็นข้อมูลส่วนตัวได้ ไม่มีการส่งทุกบทบาทให้ client แล้วซ่อนด้วย CSS

## เวลาและการตั้งค่าขั้นสูง

DAY_START 2 วินาที → DAY → NIGHT → MORNING 5 วินาที → DISCUSSION → VOTE → VOTE_RESULT 5 วินาที → วันใหม่

DAY และ NIGHT ใช้ค่า cycleSeconds เดียวกันเสมอ เริ่มช่วงละ 300 วินาที Discussion 30 / Vote 60 / Escape 120 วินาที ไม่มีปุ่มจบวัน เซิร์ฟเวอร์ตรวจ deadline ก่อนรับ action และล้าง timer/interval เมื่อจบ

หน้าสร้างห้องตั้งเวลา เงื่อนไขชนะ การโหวตเสมอ การเผยบทบาท ความจุกระเป๋า อายุของตก วันสูงสุด ตัวคูณความยาก/การเกิด/พลังงานเดินทาง และภารกิจได้

## โลกและทรัพยากร

เกาะเดียว 13 พื้นที่: แคมป์ ป่าโปร่ง ป่าดงดิบ หมู่บ้าน ทุ่งราบ ภูเขา ถ้ำ ซากวิหาร ภูเขาไฟ ซากเรือ ชายหาด ทะเลสาบ และโรงงานร้าง

แผนที่ขนาดใหญ่ลาก/ซูมได้ มีมินิแมปและปุ่มกลับตำแหน่งตัวเอง แสดงเส้นทาง ผู้เล่น ภารกิจ และภัยในพื้นที่ เดินตามเส้นเชื่อมเท่านั้น ใช้พลังงาน 5–25 คูณค่าที่ตั้ง การเดินมีผลทันทีเมื่อ server ยอมรับ ไม่มี travel delay แยก

แต่ละวัน server สุ่มของใหม่ตาม weighted loot tables ใน world.ts ปริมาณสัมพันธ์กับจำนวนผู้เล่นและ spawnMultiplier ค้นหาของเพิ่มใช้พลังงาน 10

กลางคืนเดินกลับแคมป์หรือเสี่ยงอยู่ข้างนอกได้ ตำแหน่งผู้เล่นบนแผนที่สาธารณะเป็นตำแหน่งก่อนค่ำ ตัวเองเห็นตำแหน่งจริงและคนที่อยู่ด้วยกันจาก private state

## สุขภาพและกระเป๋า

เริ่มสุขภาพ พลังงาน ความอิ่ม น้ำ 100 มีอาหารและน้ำอย่างละ 2 พลังงานสูงสุด 100

| ของ | ฟื้นฟู |
| --- | --- |
| อาหาร | พลังงาน 25 / ความอิ่ม 35 |
| ผลไม้ | พลังงาน 10 / ความอิ่ม 15 |
| อาหารกระป๋อง | พลังงาน 20 / ความอิ่ม 15 |
| เครื่องดื่มชูกำลัง | พลังงาน 35 / ความอิ่ม 15 |
| น้ำ | น้ำในร่างกาย 35 |
| ยา | สุขภาพ 25 |

พักทุก 20 วินาที แคมป์ฟื้นพลังงาน 20 และสุขภาพ 5 ที่อื่นพลังงาน 10 เมื่อหิว/ขาดน้ำมากฟื้นได้เพียง 5 ทุก 10 วินาทีในช่วงเล่นความอิ่มลด 1 น้ำลด 2 ต่ำมากจะเสียสุขภาพ เช้ามี event และใช้อาหาร/น้ำอัตโนมัติตาม survival system คนบนเรือแล้วปลอดภัยระหว่างรอออกเดินทาง

กระเป๋าเริ่ม 8 ช่อง อัปเกรด 12/16/20 หรือค่าที่ตั้งไว้ ไอเทมทุกชิ้นใช้ 1 ช่อง อัปเกรดที่แคมป์หรือโรงงานเท่านั้น ใช้เชือก 2 โลหะ 2 ชิ้นส่วน 1 ตรวจความจุทุกช่องทางรับของรวมทั้งการแลกทั้งสองฝ่าย

วางของเป็น world loot มี id ตำแหน่ง จำนวน และวันหมดอายุ (เริ่ม 2 วัน ตั้งได้ 1–3) หยิบได้ที่เดียวกันเท่านั้น คนเก็บก่อนมีสิทธิ์ก่อน ผู้ตายทิ้ง normal inventory ทั้งหมด แต่บทบาท เป้าหมาย และหลักฐานไม่อยู่ใน loot

## มอนสเตอร์

4 ต้นแบบ: หมาป่าป่า อสูรหิน ผู้พิทักษ์วิหาร อสูรแมกมา แต่ละตัวมี HP damage detection aggression เขตอาศัยและกำหนดเคลื่อนที่ของตัวเอง AI เดินตามเส้นเชื่อมภายในเขตอาศัย ไม่เดินเข้าแคมป์

ความยากเพิ่มวันละ 15% สูงสุด ×2.5 โดยค่าเหล่านี้ตั้งได้ ส่งผลต่อ HP damage จำนวน โอกาสตรวจจับ ความถี่เคลื่อนที่ และการตรวจพบในพื้นที่ข้างเคียงเมื่อความยากสูง รังที่ป่า/ถ้ำ/วิหารเพิ่มการเกิด ทำลายรังด้วยพลังงาน 15 ลด HP รัง 20 จนหมด แล้วจำนวนเกิดลดในวันถัดไป

รับมือ encounter ด้วยการลอบผ่าน (-15 พลังงาน), ล่อด้วยอาหาร 1, ใช้คบไฟ 1 (ใช้ไม่ได้กับอสูรแมกมา), หรือต่อสู้ (-15 พลังงาน) กลุ่มใหญ่มีโอกาสผ่านและ damage สูงขึ้น ผ่านแล้วปลอดภัย 45 วินาที ปล่อย encounter ค้างเสี่ยงถูกโจมตี

## Spy และการตาย

Spy ลงมือได้ 1 ครั้งต่อคืน: ลอบฆ่าหรือทำลายเรือ ตรวจ role/phase/alive/connection/location/encounter/สิทธิ์ทุกครั้ง

ลอบฆ่าได้เฉพาะคนที่อยู่ด้วยกัน ก่อวินาศกรรมได้ที่ชายหาดเท่านั้น ลดส่วนเรือที่สร้างแล้ว 2 ไม่ติดลบ

แจ้งเหตุฆาตกรรมต่างกันสำหรับคนจุดเดียวกัน ใกล้เคียง และไกล ไม่ใส่ชื่อคนฆ่า ชื่อเหยื่อ หรือพิกัดคนฆ่า พยานเห็นเพียงเงาคน ไม่ยืนยันบทบาท

ระหว่างคืนยังไม่เปิดเผยตัวเหยื่อและ loot จุดเกิดเหตุแก่ทุกคนจนเช้า คนที่อยู่ตรงนั้นเห็นของในพื้นที่ได้ ผู้ตายเป็นผู้ชมทันที ทำ action รวมถึงแชตไม่ได้ และไม่ได้รับ private state ของคนอื่น

เป้าหมายส่วนตัวจากรุ่นแรกคงเป็นโบนัสท้ายเกม ไม่ใช่ตัวกำหนด role หรือผลแพ้ชนะฝ่าย

## ภารกิจ โหวต และหนี

ภารกิจส่งทรัพยากรจริงตามจุดที่ตั้งไว้ได้สูงสุด 6 ข้อ เรือที่ชายหาดใช้ไม้ 6 โลหะ 4 เชือก 3 ชิ้นส่วน 2 ต้องยืนชายหาดเพื่อบริจาค

ผู้มีชีวิตโหวตคนอื่นได้ 1 ครั้ง รอผู้ที่เชื่อมต่อครบหรือ timeout คะแนนสูงสุดถูกกำจัด เสมอเลือกไม่กำจัด/สุ่ม/โหวตซ้ำ 1 ครั้งได้ ถ้าโหวตซ้ำแล้วยังเสมอไม่กำจัด การเปิดเผย role ผู้ถูกกำจัดตั้งได้

กำจัด Spy หมดไม่จบเกม ยังต้องทำภารกิจและเรือครบ จึงเปิด ESCAPE ต้องเดินทางตามเส้นทางไปชายหาดและกดขึ้นเรือ ไม่มีขึ้นเรือระยะไกล คนขึ้นแล้วออกไปเก็บของอีกไม่ได้ ที่นั่งเท่าจำนวนผู้เล่น หนีไม่ทันถือว่าอยู่บนเกาะ

Survivor ชนะตามที่ตั้ง: หนีอย่างน้อย 1 / ผู้มีชีวิตฝ่าย Survivor ทุกคน / จำนวนขั้นต่ำ ผู้หนีจริงได้สถานะผู้ชนะฝ่าย Survivor

Spy ชนะตามที่ตั้ง: ขัดขวาง Survivor ไม่ให้ทำเงื่อนไขหนีสำเร็จ หรือมี Spy อยู่รอดจนจบ หากใช้เงื่อนไขอยู่รอด ทั้งสองฝ่ายอาจบรรลุเงื่อนไขพร้อมกันได้

จบแสดงผลฝ่าย บทบาททุกคน เป้าหมายโบนัส และ timeline ทั้งหมด บันทึกแยกแต่ละเกม ไม่รวมคะแนน/ของกับเกมก่อนหน้า

## Role API สำหรับเกมในอนาคต

ประกาศ RoleDefinition[] เป็นอาร์กิวเมนต์ที่สามของ GameRegistry.register มี id/name/min/max/defaultMax/thresholds และ autoFill หนึ่งบทบาท

GameService/room serialization ส่ง definitions ให้ RoleConfiguration ใน CreateRoom/Lobby รับ settings.roleConfig และ socket room:roles ผ่าน schema กลาง roles.ts เกมเรียก resolveRoleCounts()/assignRoles() เพื่อคำนวณและสุ่มตาม BaseGame contract

## ผลตรวจและข้อจำกัด

- Client TypeScript และ strict typecheck ของ Island/config/world/roles/lock ผ่าน
- Island tests 16 ชุดผ่าน รวม real Socket.IO 4/6/8/10/12/15 connections, host role edits, readiness reset, locked roles, simultaneous movement/pickup, private snapshots, rejoin และ result persistence
- ครอบคลุม equal timers, role distribution, adjacency, capacity/upgrade, drop/expiry, assassination/witness/death loot, sabotage permissions, mission/boat/escape location, ties, spectators, monsters/nests และ setup lock
- Regression client room connection 5 ชุด / server rejoin เดิม 3 ชุดผ่าน
- React static render DAY/NIGHT/MORNING/VOTE/ESCAPE/FINISHED ผ่าน

ใช้ DB fixture และ authenticated-user fixture กับ handlers จริง ไม่ได้ทดสอบกับ PostgreSQL production หรือล็อกอินจริงในงานนี้

node_modules ใน ZIP เดิมมี Windows binaries, dependencies บางตัวขาด, Prisma client เก่า และเครื่องตรวจไม่มี Chromium จึงยังไม่ยืนยัน full production build หรือ browser interaction ของ pan/zoom/dialog ให้ติดตั้ง dependencies/generate Prisma และทำ browser smoke test ก่อน deploy

สถานะเกมอยู่ในหน่วยความจำตาม GameManager เดิม reconnect ภายใน process เดิมได้ หาก server restart ใช้ recovery/abort เดิม ไม่อ้างว่ารองรับ resume ข้าม process, horizontal scaling หรือ local shared-device mode
